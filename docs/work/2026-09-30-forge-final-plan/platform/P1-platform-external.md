## A. Seven ecosystems: contracts and how adoption developed

### 1. Model Context Protocol: a reusable block protocol for agents

**Contract.** [external] A server exposes named tools through `tools/list` and `tools/call`, with descriptions, JSON Schema `inputSchema`, optional `outputSchema`, and structured/content results. Resources expose URI-addressed context through listing and reading, with metadata such as MIME type; resource discovery is distinct from invoking an action. Prompts are another server primitive. This is a language-neutral callable/context boundary, useful for exporting Forge capabilities. [external](https://modelcontextprotocol.io/specification/2026-07-28/server/tools) [external](https://modelcontextprotocol.io/specification/2026-07-28/server/resources) [external](https://modelcontextprotocol.io/docs/2026-07-28/sdk)

**SDK and author path.** [external] Official SDKs cover multiple languages and both server/client construction; the current SDK page grades them by protocol completeness and maintenance commitment. Anthropic's November 2024 launch supplied an open protocol, SDKs, local Claude Desktop integration, and prebuilt connectors. Authors could connect a real data source rather than first invent host integration plumbing. [external](https://modelcontextprotocol.io/docs/2026-07-28/sdk) [external](https://www.anthropic.com/news/model-context-protocol)

**Discovery and registry.** [external] The official registry stores `server.json` metadata, reverse-domain/GitHub identity, package or remote locations, and launch/configuration information. Package registries host executable artifacts; downstream catalogs provide curation. Namespace verification and takedown exist; code scanning is delegated. The inspected registry documentation still calls the service preview and warns of breaking changes/data resets. [external](https://modelcontextprotocol.io/registry/about)

**Trust and signing.** [external] Tool annotations are untrusted unless supplied by trusted servers. The security guidance addresses token passthrough, confused-deputy behavior, and consent. Registry identity verification does not constitute a universal signed-artifact or sandbox guarantee; those assurances belong to artifact distribution and host policy. [external](https://modelcontextprotocol.io/specification/2026-07-28/server/tools) [external](https://modelcontextprotocol.io/docs/2025-11-25/tutorials/security/security_best_practices)

**Versioning and compatibility.** [external] The inspected latest specification resolves to `2026-07-28`: protocol version, identity, and capabilities travel per request, with supported-version errors and optional discovery. It distinguishes legacy `2025-11-25` and earlier initialization-handshake implementations from modern and dual-era implementations. A server package version and protocol revision are separate compatibility dimensions. [external](https://modelcontextprotocol.io/specification/2026-07-28/basic/versioning)

**Composition.** [inferred] Hosts choose server endpoints/processes and credentials, discover their capabilities, and decide which tools/resources to expose. Forge still needs its own rules for connecting block instances, satisfying capability requirements, resolving versions, and owning cleanup. A tool catalog alone does not express that graph. The distinction follows from MCP's callable boundary and Backstage's explicit dependency/lifecycle model. [external](https://modelcontextprotocol.io/specification/2026-07-28/server/tools) [external](https://backstage.io/docs/plugins/new-backend-system/)

**Growth and friction.** [external] The launch named early enterprise adopters and editor/tool partners. The September 2025 registry announcement subsequently addressed distribution/discoverability across downstream marketplaces. [inferred] The adoption incentive is amortizing one integration across hosts; the documented later registry work illustrates that interoperability and discovery develop separately. Protocol changes and uneven host implementation remain reasons to publish an actual compatibility matrix. [external](https://www.anthropic.com/news/model-context-protocol) [external](https://blog.modelcontextprotocol.io/posts/2025-09-08-mcp-registry-preview/)

### A schema-first surface with one authority

| Mechanism | Primary evidence | Implication for Forge [inferred] |

Declare the dialect and supported subset. |

Terraform's distinction between validation and planning is evidence for a second semantic/environment stage. [external](https://developer.hashicorp.com/terraform/cli/commands/validate)

[inferred] The composition format needs named block instances, explicit capability bindings, version constraints, and a finite documented override order. Do not make agents invent an arbitrary expression language. Start with references and typed mappings for proven compositions; add more expressiveness when real templates require it. Backstage's composed schemas and Terraform's provider addresses show how package identity and configuration can remain separate. ### Generated docs and llms.txt-style access

[external] `llms.txt` is a proposal for an agent-readable documentation index, with Markdown links and optional context. The inspected version is labeled v2. MCP publishes a documentation index, and n8n offers Markdown pages and a full index. This is a retrieval convenience; the cited proposal does not demonstrate a general accuracy improvement or guarantee that every harness automatically reads it. [external](https://llmstxt.org/) [external](https://modelcontextprotocol.io/docs/2026-07-28/sdk) [external](https://docs.n8n.io/sitemap.md)

[inferred] Publish a concise index linking to versioned block contracts, capabilities, schemas, examples, trust policy, error codes, and migrations. Offer bounded per-block/per-version documents and downloadable schema artifacts. Keep a full-text bundle optional: a growing catalog should not require every author/agent to ingest all documentation. Reference docs describe fields; examples show the smallest useful composition and its expected output; migration docs explain what changed. Generated schema docs do not replace those tasks. Backstage provides the generated-reference precedent; Anthropic's tool-design guidance supports testing descriptions/examples against actual agent tasks. [external](https://backstage.io/docs/tooling/cli/module-config/) [external](https://www.anthropic.com/engineering/writing-tools-for-agents)

### Validators, explain/plan, scaffolding, examples

[inferred] The following is a proposed product behavior, not a claim that these Forge APIs/verbs exist:

1. **Inspect:** machine-readable installed/discoverable capability catalog, manifest, schema, version, support/trust information, and a minimal composition example.
2. **Scaffold:** one external-author block plus a template that consumes an existing capability through public APIs. Include package exports, manifest/schema, one useful implementation, a runnable conformance check, and publishing metadata. Preserve Forge's one-package constraint; authors publish separate third-party packages.
3. **Validate:** reject malformed config, unknown fields, duplicate identities, missing providers, incompatible capability versions, invalid references, and unsupported host requirements with stable error codes and paths.
4. **Explain:** return resolved blocks/bindings, exact versions, config origins/override order, available and unavailable capabilities, effects, requested authority, and missing prerequisites. This path must parse inert manifests/config; importing arbitrary JavaScript can itself execute code.
5. **Plan/preflight:** make any provider/network/auth reads explicit and optional. Clearly separate pure resolution from a connected check; show what is known, unknown, and proposed. Terraform planning normally refreshes remote objects, so “dry-run” should not imply “offline.”
6. **Run:** execute the same resolved graph through public APIs with lifecycle ownership, cancellation, cleanup, and a durable outcome. Redact secrets in diagnostics, optional visualization apps, external API responses, logs, and persisted plan artifacts.
