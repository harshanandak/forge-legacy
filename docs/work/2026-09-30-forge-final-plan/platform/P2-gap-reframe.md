## E. Minimal platform promise for 0.1.0

**Proposed promise [inferred]:** “Install one Forge package. Using its public catalog, schemas and APIs, a developer or agent can define a trusted block with a new capability, compose it with built-in blocks in validated config, inspect what will run, and invoke the same solution through supported native harness adapters. Authoritative work stays in Kernel; adoption of Forge's delivery template is optional.”

### Ship the smallest complete platform slice

1. **A public block contract and catalog.** Namespaced definition and instance IDs; separate implementation/interface/config/manifest versions; provided operation/input/output schemas; required capabilities with explicit bindings; error/status/evidence rules; source identity, trust and ownership. Built-ins and outside blocks use the same resolution model. Start with trusted startup-only actions whose schemas and requirements are declarative; support a new capability name in that class, not only known renderers. Built-in stateful owners keep their current lifetimes behind documented service clients. Mark broader third-party stateful/effectful/supervised forms by support status; do not pretend pure-action proof certifies them.
2. **A first-class config API.** Public typed schemas/docs, one pure compiler with deterministic precedence/validation and full origins, block/solution scaffold, explain/dry-run and structured remediation errors. Emit a normalized plan that runtime/harness consumers actually use. Config describes desired composition; it cannot self-authorize code, effects, approvals or progress.
3. **Real outside source selection.** Resolve an independently installed pinned package and a local-author source through the same descriptor/binding contract. Keep installation explicit/manual; no download during preview. Separate package identity/compatibility from invocation admission. Pin source/dependency closure and document supported module format; unsupported closure/format refuses before execution. This is required work to price, not an existing benefit of `require()`.
4. **Useful reference capabilities and solution.** At minimum Contracts, Flow, local Memory, narrow Kernel client/lifecycle, config/catalog and native projection are usable through installed public entries. Expose the policy/worktree/review/delivery operations the reference solution needs through supported clients/bridges; keep internals private. TDD delivery plus small-change variants exercise the same compile/bind/invoke path, with intact owning guards. No independent shadow state for stage progress.
5. **Native connection with an open adapter seam.** Generate native operation/skill surfaces from a resolved solution; preserve user content and capability/permission refusals. Prove two real installed harnesses for the new solution; retain the earlier plan's applicable four-harness certification for promised existing behavior. “Any harness” is the open architecture target, not an untested claim about every host/version at launch.
6. **A public authoring proof and compatibility bar.** Clean consumer imports, author/consumer conformance, new capability + binding, refusal/admission cases, lifecycle/restart evidence and public-docs-only agent completion. Freeze the selected supported 0.1.x contracts/IDs and explicitly version migrations; experimental scope is named, not an excuse for silent patch breaks. Retain the exact-artifact release campaign and add platform strata.

| --- | --- | --- | --- |

Define discovery versus installation versus execution admission separately. | Shipped first-party capability/template catalog and validateable publishing descriptor; independently installed package selection in the proof. ### Concrete end-to-end proof: an outside “migration-note advisor” block

**Why this scenario:** it introduces `community.migration-notes.assess`, a new capability—not another renderer/provider of a host-preselected receipt interface. The solution helps a user's own release UI/agent spot a public-API change without an accompanying migration note. It is advisory and read-only; accepted delivery/gate outcomes remain owned by existing services. [inferred]

**Author receives only** the frozen public Forge docs/catalog/schema assets, the installed candidate package and this brief: “Create an advisor that consumes normalized changed-file/API facts plus provenance context, reports missing migration guidance, and runs as a custom solution in Codex and Cursor.” The author works outside Forge's source tree; one test arm uses a cold agent with no private-source access. The host supplies explicit code trust; the author cannot approve its own execution. No core patches, new named switches in each harness, or hidden maintainer integration are allowed. [proposed acceptance]

1. **Author builds the block.** Scaffold a manifest, one small implementation and conformance sample. Declare the new namespaced operation, bounded input/output JSON schemas and compatible public Contracts dependency. Implement an assessment such as “public API touched and no migration-note artifact → advisory finding.” The block has no Kernel write, remote write or unrestricted host client supplied. Its result is an advisory assessment; it cannot forge an accepted RunReceipt or approve a merge.
2. **Package it independently.** The author supplies a separate local package/tarball with an exact version and supported entry, depending on Forge public entries only. An independently managed consumer installs it explicitly beside Forge. Discovery validates the descriptor/source closure without importing implementation or conformance code; explain lists its capabilities, bindings, order, schemas and required trust.
3. **Compose through config.** A user-authored `release-advisor` solution binds built-in Contracts validation, a built-in normalized change-input operation, Memory recall and Flow to the new assessment operation. A generic output/evidence adapter returns the finding to the user's UI/native tool; an authorized built-in Kernel client may record run evidence for a connected version. No TDD/ship/review stages are needed for this advisory solution. A stateless variant omits issue tracking; neither invents alternate issue authority.
4. **Agent generates and repairs config.** The authoring agent discovers capabilities/schemas, creates bindings and selects a template or writes solution data. Introduce a misspelled requirement, incompatible interface, invalid option and cycle; validator/explain must identify path/source/expected contract and repair guidance before imports. Generated docs/schema and runtime must agree.
5. **Admit and run through Codex.** Install the selected solution's native surface through the supported adapter, preserving existing user files. In a real installed Codex session, discover/invoke it on a fixed fixture, obtain the advisor result and host-observed evidence, and demonstrate correct advisory/refusal behavior. Record candidate/block/config/schema/source/adapter/harness identities and actual transcript.
6. **Run the same solution through Cursor.** Use the same manifest, config, schemas and fixture through a real installed Cursor session. Only selected host adapter/invocation-specific auth/trust inputs differ; the block and domain composition do not. Native discovery/invocation must reach the generic runtime, not bypass it with a manually installed unrelated script. Validate equivalent domain results/evidence rather than identical model prose.
7. **Exercise trust, authority and lifecycle boundaries.** Unadmitted/wrong-source execution and conformance leave an import-time sentinel untouched; changed source requires fresh admission; protected mutation/custom approval attempts refuse through owning checks. Missing required capability yields explicit INCOMPLETE/refusal, never a successful empty run. Close owned resources, restart the connected solution with prior recorded context or explicit refusal, and preserve history/user content.
8. **Prove reuse/substitution and artifacts.** Swap Memory's supported enrichment implementation while retaining its local floor and the advisor consumer contract; revalidate bindings/results. Install the exact Forge candidate and outside block in a clean directory with no checkout assets/private imports, run the proof, and bind receipts to artifact/source/config identities. If binaries advertise this platform path, certify external loading/invocation there too; do not infer it from npm success.

**Required evidence set:** author brief and public-docs input identity; block source/package/manifest; schema-generated config and explain output; conformance and negative-case results; native Codex and Cursor transcripts/versions; immutable artifact/config/source bindings; resource cleanup/restart evidence; author intervention log. Machine-check that no private imports/core changes were needed and all named obligations were exercised. A maintainer fixing the integration after the author gets stuck is useful failure evidence, not a passing public-docs-only result. [inferred]

**Pass criterion:** the independent author/agent produces the new capability and working composition without human implementation help; both real harnesses use the same public platform path; negative cases refuse correctly; mandatory gates/Kernel authority remain intact; artifact identities and lifecycle evidence are complete. Any missing native transcript, ignored config, private import, core special-case or unverified source/admission keeps platform acceptance **INCOMPLETE**. This report specifies the scenario; it does not execute or certify it. [proposed acceptance]
