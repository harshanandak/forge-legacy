## A. Who Forge is for, and what it does

**Primary user:** an engineer or maintainer operating AI coding sessions in a Git repository, especially across resets, different harnesses, and concurrent worktrees. **Job:** make the work, authority, decisions and delivery evidence survive the session; make the next action discoverable without trusting a model's recollection. README explicitly names solo builders, teams, quality-conscious engineers and maintainers. [read: `README.md:12`, “Who it's for”, “What you get”; `AGENTS.md:125`]

**Owner value:** fewer lost obligations and duplicate claims, one configurable workflow, fewer per-harness instructions to maintain, and a defensible merge/release decision. The live Kernel contains 1,659 tracked records, and merged history repeatedly repairs ownership, worktrees, memory recall, and delivery safety. This is real dogfooding evidence of recurring problems; it does not measure minutes saved or prove market demand. [ran: M4; read: merged PRs #523, #524, #538, #541, #550, #589]

**Boundary:** Forge should remain an installable control plane and library of composable capabilities. A prompt pack alone does not supply durable authority or evidence. A new dashboard, hosted service, graph database, execution-provider marketplace, or mandatory end-to-end orchestration stack is not necessary to deliver the primary job. Preserve optional composition rather than requiring every capability at setup. [read: `AGENTS.md:6`; `lib/memory-core/src/backend-registry.js:85`; common one-package constraint; inferred]
