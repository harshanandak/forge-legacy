Decisions needed: adopt the defaults in the nine decisions below. Keep the six functional boundaries and the previously selected launch scope. The material correction is to make reusable invocation and authority contracts independent of Forge delivery, and place delivery contracts, policies and execution structures above them. A fresh repository removes the need to build forwarding facades before establishing those seams.

This is a design evaluation, not a module inventory or implementation authorization. Only this output file was written. No installs, network, code execution, commits, tracker writes or source changes were performed. The shared brief's inventory columns are adapted to design tables because the assigned lane explicitly excludes a code inventory. Test names below identify preservation evidence; they are not passing-test claims.

## 1. Boundary verdict: keep six layers, separate their internal concerns

The plan's layer model is already the right shape. A layer is an ownership/dependency boundary, not a package or compulsory service. The wire leaf belongs inside Contracts, and engines use injected ports rather than its assembly implementation. No two layers need to merge. Three internal separations are necessary: Contracts wire versus assembly; Kernel transaction/storage authority versus domain acceptance contracts; Flow single-operation execution versus selectable reference execution. `read: Plan:258–296; inferred verdict; decisions below`.

| --- | --- | --- | --- | --- |

**Shared state assessment:** sharing a SQLite file is not itself a seam violation; sharing authority or initialization is. Existing project knowledge tables may stay physically with the driver, with Memory owning semantics through a knowledge port. Kernel serializes its protected writes, and Memory cannot bypass that with exposed SQL. Separate migration ownership is essential for the issue-free device database. Knowledge indexes and PR observations need accepted cursor/source revision, rebuild and lag semantics; neither may silently become current authority. Config edits have their own CAS and owned-file reversal and are not Kernel work-state edits. `read: Plan:296,315,580,1254–1269,1385–1389; Storage:41–51; inferred assessment`.
