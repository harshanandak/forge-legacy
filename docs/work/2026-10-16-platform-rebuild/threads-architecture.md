## What happened and where it ended

**Read: Architecture p.0–11.** The original question was how to connect adapters, independently usable Memory, and independently usable Flow into a coherent future. A pasted earlier recommendation at p.3 proposed control-plane-first sequencing, Kernel authority, Companion execution, adapter translation, thin skills, plugins as packaging, and non-authoritative recalled knowledge. The first synthesis shortened the path: prove useful standalone journeys, probe two different harnesses early, and establish evaluation before adopting providers. “Memory product contains Kernel” and “recalled memory is not authority” were explicitly separated.

**Read: Architecture p.14–218, September 12.** Planning and research preservation expanded into facade implementation, unsafe T0 delivery wiring, Windows helper failures, and false-green validation fixes. The archive was reported merged as [PR #561](https://github.com/harshanandak/forge/pull/561); Windows workflow work as [PR #557](https://github.com/harshanandak/forge/pull/557); validator repairs as [PR #562](https://github.com/harshanandak/forge/pull/562). The facade slice remained parked with native delivery incomplete. Owner frustration concerned hours spent on a planning task and repeated validation, not a request to weaken evidence.

**Read: Architecture p.219–410, September 14.** The owner redirected planning around independent APIs, user-owned setup, bare capabilities, one distribution, optional opinionated workflows, and future community sharing. The assistant repeatedly preserved old package boundaries too strongly. The explicit correction at p.341 ended Memory/Flow as permanent package boundaries; they became presets. Twenty-four inventory families reduced to seven candidate namespaces, then eight when Feedback passed an independent-consumer test. Astra reviews revised delivery mechanics and trust semantics, and a Companion red-team produced further corrections. These were planning/source verdicts, not installed implementation proof.

**Read: Architecture p.411–503, September 15–17.** The owner parked the large architecture implementation to repair the development environment: unreliable Windows tests, repeated validation, branch-refresh churn and slow merges made a 5–10 PR/day target unrealistic. Graft was evaluated as an exploration aid, failed before graph construction, and accidentally became a distraction. The owner restored testing/pushing/merging as the primary objective at p.500; the capability architecture became a constraint, not another prerequisite.

**Read: Architecture p.504–1397, September 18–24.** A delivery wave landed package/lint fixes, a protected workflow writer, CI failure propagation, fixture and Flow batching work, package-name discovery optimization, push-proof/runner repair, readiness-scanner optimization and resource budgets. Required CI repeatedly exposed unrelated or incompletely diagnosed Windows timeouts after earlier successful PR checks. Shepherd startup and readiness defects remained visible across several PRs. Budget control became truthful but did not establish fast feedback or eliminate stalls.

**Read: Architecture p.1398–1523, September 24–26.** Shepherd classification/evidence work was implemented and reviewed, but broad validation failed. Further investigation rejected a shutdown-hang theory after discovering 15 exclusive test files had not started. Timeout-output preservation and duplicate backend-lookup removal were committed separately. The budget-four run still failed after 28m40s, with seven timeout observations and three missing-fixture assertions. The thread ended with local commits and hash-verified evidence preserved, no successful canonical receipt, and a continuation prompt after the repository moved to `<old-repo-root>`.

**Read: Architecture p.1515–1523. Final historical disposition:** timeout evidence/report (`189907cc`), duplicate lookup (`b519b68a`), and Shepherd (`3d7142d0`) were reported locally committed with clean worktrees and 21 verified artifacts; they were **not pushed or merge-ready**. The capability architecture was planned and archived, not delivered by this thread. Do not turn the early planning PASS or the later local commits into a rebuild-completion claim.

### Failure loops and corrected diagnoses

**Read: Architecture p.37–45, 149–181, 496–499.** Documentation archiving repeatedly entered broad validation because the selector used committed HEAD versus upstream rather than staged/untracked files, and `forge push` differed from the normal hooked Git path. Moving dependency heads invalidated downstream validation. **Inferred:** the root prevention is one documented planning/evidence-selection API shared by entry points, cheap checks before expensive ones, and final validation only on a stable candidate. A new timeout or another full rerun does not repair the mismatch.

**Read: Architecture p.237–240, 472–503.** “Save research” became an unauthorized PR; recommendations were called locked before discussion; Graft displaced the delivery objective; previously agreed composition choices were reopened. **Inferred:** preserve task scope, decision status and supersession as structured context. Do not convert every newly mentioned idea into the next execution objective.

**Read: Architecture p.812–818.** Keeping four known prerequisite fixes on mutually failing branches created a local validation dependency cycle; owner-approved combination retained separate commits. **Inferred:** file isolation does not imply proof independence. Plan integration candidates and known-failure dependencies before spending another full run.

**Read: Architecture p.951–954, 1034–1040, 1452–1454.** Counts initially double-counted nested suites; negative-test output was mistaken for gate failures; partial JUnit parsing associated failures with wrong names; synchronous mocks missed new async callers. **Inferred:** use typed terminal results and one canonical report parser, preserve failed attempts, enumerate the full caller boundary and never infer pass from liveness or a partial count.

**Read: Architecture p.1128–1150, 1215–1223, 1259–1281.** SQLite/holdout CI cases could be tens of times slower than local runs; a single-write case also stalled, so batching alone could not explain the failure. Diagnostic CI narrowed cost to writes/initialization without reproducing the original timeout. **Inferred:** retain the open causal question; port an optimization only for its measured benefit, never as an invented root-cause cure.

**Read: Architecture p.1459–1471.** The estimate that all test work nearly fit in 25 minutes was wrong: it counted only the first of 17 exclusive files; timeout occurred during the second, leaving 15 unstarted. That invalidated the output-drain/shutdown-hang inference. **Inferred:** capture intended inventory, started/completed/unstarted items and terminal output. Artifact existence is not complete execution.

**Read: Architecture p.693.** A failed test assertion printed inherited credential values into a tool transcript. Only names were subsequently reported; rotation was unverified later at p.753. **Inferred:** allowlist child environments and redact before assertion/log output; do not copy ambient environments into failure snapshots. This report includes no credential values.

## Agent-era lens and application to the October rebuild

**Inferred from Architecture p.267–322, 456–485 and 1132–1134:** durable value is in contracts, ownership, grants, deterministic configuration, source identity, evidence, cleanup and discoverability. These remain useful when agents improve. Step-by-step interviews, compulsory stage choreography, repetitive explanatory prompts and fixed reviewer/model assignments are compositions for a particular workflow, not core capability requirements. An expert model's approval is evidence of a review, not a protected authority transition.

**Inferred from Architecture p.237–240, 307, 472–485 and 500–503:** smarter agents still need access to prior accepted decisions and current scope. Preserve an explicit distinction between proposed, accepted, superseded, implemented and verified. Avoid trying to solve semantic drift with another universal controller. The user can build judgment loops using the same public operations, and the host mechanically enforces only the boundaries it controls.

**Read: current brief.md: decision/build-shape/workflow/no-baggage sections; platform-plan-final.md:328–369, 563–620, 947–976, 1748–1781.** October now explicitly chooses a new contract-first project, engine ports with tests, a shared invocation/config API and five-project migration. September's refactor-versus-package debates and exact eight-namespace/four-harness release train are historical inputs. They do not supersede those current decisions. The current plan also narrows outside execution and reference orchestration; do not silently bring back September's broad runtime/lifecycle promises.

**Inferred: port order for lessons, not a new implementation schedule.** Freeze the shared public contract/catalog/config/identity rules first; independently port proven authority, knowledge, execution and observation behavior behind those contracts, with one owner each; give the integration lane exports/manifests/lock/projection ownership; assemble an outside-consumer checkpoint before broad harness and migration claims. The first-party delivery workflow consumes these blocks. Its PRs, TDD stages, review policy and Shepherd semantics stay out of neutral block schemas. Known behavior and regression tests are candidates for reuse; historical file layout, no-op compatibility and ceremony are not.
