# Harness survey: Hermes, Gemini CLI, Antigravity, plus cross-harness standards

Date of research: 2026-10-16. Read-only; the only file written is this one. Follows `harness-brief.md`.

**Marks.** `read` = fetched or opened (URL or file, 2026-10-16). `ran` = a command I ran. `inferred` = my reading, not stated by a source. "Not documented" means I read the page(s) named and found no statement; it does not mean "unsupported".

## 0. Headlines that change the plan

1. **Gemini CLI has been replaced for most people.** Google stopped serving Gemini CLI to Google AI Pro/Ultra and free Code Assist-for-individuals users on **2026-06-18**. Antigravity CLI (`agy`, a Go rewrite, apparently closed source) is the successor. Gemini CLI stays up for Code Assist Standard/Enterprise licences and paid API keys, and remains an Apache-2.0 repo. [read: theregister.com/ai-ml/2026/05/20/bye-bye-gemini-cli-google-nudges-devs-toward-antigravity/5243605 (secondary press); geminicli.com/docs banner "Gemini CLI was replaced by Antigravity CLI on June 18th, 2026" (primary banner)]. Forge should treat **Antigravity as the Google harness that matters for individuals**, and Gemini CLI as an enterprise/API-key legacy lane.
2. **Antigravity's CLI docs are thin on a few things Forge needs** (no custom-command file format, no ACP, no documented memory, no CLI worktree flag). Section 3 lists each gap.
3. **One `.agents/` convention now covers most of the Google and Open-source harnesses.** `.agents/skills/` is read by Codex, Cursor, OpenCode, Pi, Gemini CLI, Antigravity; Hermes reads it via an opt-in config. **Claude Code is the exception** (its docs list `.claude/skills` only). See section 4.
4. **MCP spec 2026-07-28 is current and is a breaking revision** (stateless, no `initialize`, no sessions, no server-initiated requests; Roots, Sampling and Logging deprecated). Claude Code already speaks it on some connections. Forge's MCP server must negotiate both eras. See section 5.
5. **Hooks are not a standard.** Each harness has its own event names, config location and I/O schema (section 6). Forge projects hooks per harness; there is nothing to target once.
6. **Hermes: my local docs are older than upstream.** Installed v0.19.1; upstream latest is v0.22.2 (2026-10-15). Doc claims below come from the local v0.19.1 checkout.

**Forge should not build for Gemini CLI** (it does these natively): instruction-file loading and nesting (JIT context), skills discovery and consent, extension packaging/marketplace/gallery, policy engine, headless JSON, session resume.
**Forge must supply:** (a) one authority for issue/run state that its hooks and MCP tools both call (Gemini has none); (b) a `hooks.json`/`settings.json` projection (events differ from every other harness); (c) a `GEMINI.md`-or-`context.fileName` shim so AGENTS.md is actually loaded; (d) an MCP server whose name has no underscore and whose tool names fit 63 chars after `mcp_{server}_`; (e) evidence capture, because Gemini's checkpoints are file snapshots, not run evidence.

### 5.2 Per-standard detail and sources

**5.2.1 AGENTS.md** — steward: Agentic AI Foundation under the Linux Foundation (read agents.md footer). AAIF was formed 2025-12-09 with MCP, goose and AGENTS.md as founding projects (secondary: press-release summaries). Format: plain Markdown, no required fields; nearest file wins; explicit user prompts override (read agents.md). It lists 23 supporting tools including OpenAI Codex, opencode, Cursor, Gemini CLI, Windsurf, Amp, Zed, VS Code, Copilot coding agent (it does **not** list Claude Code, Pi, Hermes or Antigravity — the page says the list may not be exhaustive).
Evidence per harness: Claude Code [read code.claude.com/docs/en/memory §AGENTS.md]; Cursor [cursor.com/docs/context/rules]; Codex [learn.chatgpt.com/docs/agent-configuration/agents-md, redirected from developers.openai.com]; OpenCode [opencode.ai/docs/rules/]; Pi [read `packages/coding-agent/docs/cli.md:215`, earendil-works/pi]; Hermes [docs/user-guide/features/context-files.md]; Gemini CLI [docs/cli/gemini-md.md]; Antigravity [antigravity.google/docs/rules]; T3 Code [read github.com/pingdotgg/t3code README + AGENTS.md: repo has them, runtime use not described].
**Forge consequence:** write one root `AGENTS.md`; the only places it won't load unaided are Claude Code (if a `CLAUDE.md` exists, include `@AGENTS.md` in it) and Gemini CLI (`context.fileName`). Hermes picks only the first file type, so a `.hermes.md` would hide AGENTS.md; do not generate one. Antigravity caps 24,000 bytes per file and a 20,000-token shared budget; Codex caps 32 KiB combined; keep the file short or split by directory (inferred).

**5.2.2 Agent Skills** — originated at Anthropic, released as open standard; spec at agentskills.io/specification [read 2026-10-16]. Required: `name` (1–64, lowercase alnum + hyphens, no leading/trailing/double hyphen, must equal the directory name) and `description` (1–1024 chars). Optional: `license`, `compatibility` (≤500), `metadata` (string→string), `allowed-tools` (experimental, space-separated). Layout: `SKILL.md` + `scripts/`, `references/`, `assets/`. Recommended: body < 500 lines, < 5000 tokens; metadata ~100 tokens loaded at start. Reference validator `skills-ref`. The showcase (agentskills.io) lists Claude Code, Cursor, Codex, OpenCode, Pi, Hermes Agent, Gemini CLI among ~45 clients; it does not list Antigravity or T3 Code (Antigravity docs link the standard themselves).
Harness-specific extras (do not rely on in portable skills): Claude Code adds `when_to_use`, `disable-model-invocation`, `user-invocable`, `context`, `agent`, `hooks`, `paths`, …; uploads of such skills to claude.ai fail on unknown keys [read code.claude.com/docs/en/skills]. Cursor adds `paths`, `disable-model-invocation`, `icon`, `color`. OpenCode puts its extras under `metadata` (`opencode/slash`, `opencode/autoinvoke`). Codex uses a sidecar `agents/openai.yaml`. Pi uses `disable-model-invocation`. Hermes adds platform gating.
**Forge consequence:** author skills to the **spec fields only**, in `.agents/skills/<name>/SKILL.md`; mirror/symlink into `.claude/skills/` for Claude Code (the only listed harness that does not document `.agents/skills`). Put harness behaviour in `metadata` or sidecar files. MCP has an official **"Skills over MCP"** extension in a working group (read modelcontextprotocol.io/specification/latest) — track it, but no harness above documents it.

**5.2.3 Model Context Protocol** — current spec **2026-07-28** [read modelcontextprotocol.io/specification/2026-07-28/changelog]. Steward: AAIF/Linux Foundation (founding project, secondary). Server features: Tools, Resources, Prompts. Client features in the 2026-07-28 spec overview: Elicitation; Roots, Sampling and Logging are **deprecated** (kept ≥ 12 months; new implementations should not adopt). Breaking changes vs 2025-11-25:
- Stateless: no `initialize` handshake, no `Mcp-Session-Id`, protocol version and client capabilities travel in `_meta` on every request; new `server/discover` RPC (servers MUST implement).
- Server-initiated requests replaced by **Multi Round-Trip Requests**: a server returns `resultType: "input_required"` with `inputRequests` (elicitation/sampling/roots); the client retries with `inputResponses` (+ `requestState`) and a new JSON-RPC id. Every result now has `resultType`.
- `subscriptions/listen` replaces HTTP GET and `resources/subscribe`; SSE resumability (`Last-Event-ID`) removed; `ping` and `logging/setLevel` removed.
- Tasks moved to an official extension `io.modelcontextprotocol/tasks`; `extensions` field in capabilities; MCP Apps extension.
- `tools/list` and other list results require `ttlMs` and `cacheScope`; servers SHOULD return tools in deterministic order; standard headers `Mcp-Method`, `Mcp-Name`; `x-mcp-header` on tool params.
- Auth: RFC 9207 `iss` validation MUST; DCR (RFC 7591) deprecated in favour of **Client ID Metadata Documents**; `application_type` required in DCR.
- `inputSchema`/`outputSchema` allow any JSON Schema 2020-12; `structuredContent` can be any JSON value. Resource-not-found code now `-32602`. Error codes `-32020…-32099` reserved for MCP.
- Transports: **stdio and Streamable HTTP** only as standard bindings; HTTP+SSE deprecated.
**Tool-name rules (spec, SHOULD):** 1–128 chars, case-sensitive, only `A-Z a-z 0-9 _ - .`, no spaces/commas, unique per server; clients aggregating servers should prefix to disambiguate [read …/2026-07-28/server/tools]. Tool annotations must be treated as untrusted unless the server is trusted.
**Harness-imposed naming (read):** Claude Code `mcp__<server>__<tool>`, drops tools whose full name exceeds 128 chars; property names ≤64 chars `[A-Za-z0-9_.-]`; descriptions cut at 4,096 chars (upfront) [code.claude.com/docs/en/mcp]. Gemini `mcp_{server}_{tool}`, other chars → `_`, truncates at 63, no `_` in server names [docs/tools/mcp-server.md]. Hermes `mcp_<server>_<tool>`, non-alnum → `_` [docs/user-guide/features/mcp.md]. Pi `mcp__<server>__<tool>`, every char other than letters/digits/`_` → `_` and collisions get a hash suffix; server names letters/digits/`_`/`-` [docs/mcp.md, earendil-works/pi]. OpenCode prefixes `<server>_` [opencode.ai/docs/mcp-servers/]. Antigravity, Cursor, Codex: not stated in the pages I read.
**Forge consequence (inferred):** generate MCP tool names from the operation catalog as lowercase `a-z0-9_` only, short (target ≤ 40 chars), under a short server name without `_` or `.` (e.g. `forge`), so every harness's prefixed form stays under 63 and 128 and survives Pi/Hermes character remapping without collisions. Return `structuredContent` plus a text copy (spec says SHOULD). Expect a harness to cap tool-result size (Claude Code: 25,000 tokens default). Implement both protocol eras (`server/discover` plus legacy `initialize`) until the harnesses move; Claude Code already negotiates per server (`MCP_PROTOCOL_NEGOTIATION`).

**5.2.4 Agent Client Protocol (ACP)** — JSON-RPC 2.0 between an editor/client and an agent subprocess; methods `initialize`, `authenticate`, `session/new`, `session/load`, `session/prompt`, `session/set_mode`, `session/cancel`, client-side `session/request_permission`, `fs/*`, `terminal/*`, `elicitation/create`; agent `session/update` stream [read agentclientprotocol.com/protocol/overview; docs under `/protocol/v1`; steward not stated on that page]. Agents list (read agentclientprotocol.com/get-started/agents): Claude (Zed adapter), Codex CLI (`codex-acp`), Gemini CLI, OpenCode, Cursor, Pi (`pi-acp`), Hermes Agent; Antigravity and T3 Code absent. Clients list (read …/get-started/clients) has Zed, JetBrains, Neovim, Emacs, VS Code extensions, Obsidian etc.; **T3 Code is not listed**.
Detail checked: Cursor `agent acp` [cursor.com/docs/cli/acp] — project/user `mcp.json` only, team MCP servers not supported in ACP mode, extension methods `cursor/ask_question`, `cursor/create_plan`; OpenCode `opencode acp` [opencode.ai/docs/acp/] — AGENTS.md, MCP, custom commands work; `/undo` `/redo` unsupported; Hermes [docs/user-guide/features/acp.md]; Gemini [docs/cli/cli-reference.md].
**Forge consequence (inferred):** ACP is the one *session-driving* protocol most harnesses share, but Forge's plan already says it does not drive sessions (T3 Code and the Codex App Server do — plan §3.5, `platform-plan-final.md:978–1124`). Forge should **not** implement ACP agent or client. It should only make sure that its MCP tools, hooks and skills work when the harness is driven over ACP (Cursor's ACP mode excludes dashboard-level team MCP servers, so project-level `mcp.json` is the safe carrier).

**5.2.5 Agent2Agent (A2A)** — Linux Foundation project (originally Google), Technical Steering Committee from AWS, Cisco, Google, IBM Research, Microsoft, Salesforce, SAP, ServiceNow; the site shows a banner "A2A is joining the Agentic AI Foundation"; "What's New in v1.0" exists (read a2a-protocol.org/latest). One source says v1.0 shipped early 2026 (secondary: search result summaries). Relationship: MCP = agent↔tool; A2A = agent↔agent. I did not check Pi, Hermes or T3 Code docs for A2A specifically (so: unknown).
**Forge consequence (inferred):** no harness is an A2A *server* we could address uniformly; A2A is not a viable cross-harness handoff today. Handoff goes through Forge's own authority (issue/run records) and MCP tools, not A2A.

**5.2.6 Not standards (so Forge projects per harness):** hooks (schemas differ, §6), plugin packaging (Gemini `gemini-extension.json`, Antigravity `plugin.json`, Hermes `plugin.yaml`+Python, Claude/Cursor/Codex/OpenCode/Pi each own), slash-command files (Gemini TOML; Hermes `quick_commands`; Antigravity none documented), permission and sandbox config, settings files.
